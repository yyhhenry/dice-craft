## 一、本期目标

本期重点是把 DiceCraft 从"能展示与运行场景"推进到"更像一个可玩的桌游应用"：

1. 引入角色语音生成，让 NPC 重要台词可以配音播放
2. 完成地图点击交互、角色/覆盖物动作菜单与移动动画
3. 调整多 Agent 架构为 all-primary：主模型统一控制用户可见输出
4. 增强聊天消息渲染，支持 Markdown、GFM 表格与代码高亮
5. 强化模型消息、工具读文件、安全边界和运行稳定性

## 二、角色语音系统

新增 `src/voice/` 模块，接入 MiMo TTS，提供两个 primary 专用工具：

| 工具 | 说明 |
|------|------|
| `voice_design` | 根据声音描述与样本台词生成角色音色样本，可保存为游戏资产 |
| `voice_speak` | 读取已有音色样本，生成一条带语音字段的聊天消息 |

语音设计从"朗读全文"改为"高光台词"模式：GM 从角色消息中选取 1-2 句最有表现力的短台词生成音频，而不是把整段文本念完。这样既避免语音冗长，也更适合桌游关键时刻的演出。

### 后端集成

- `WorkspaceConfig` 新增可选 `tts` 配置，独立于主模型 API 配置
- `ChatMessage` 新增可选 `voice: { asset, duration }`
- `voice_speak` 生成的音频保存到 `data/sessions/<sessionId>/voice/`
- 新增 session voice 访问路由，前端可通过消息中的 asset 播放音频
- `read` 工具识别 WAV 文件并返回时长、采样率、声道、位深等元数据，而不是误按文本读取

### 前端表现

新增 `VoicePlayer` 组件，语音消息在普通气泡下方显示播放按钮、进度条和时长。新 WebSocket 消息可自动播放；历史消息不会自动播放，避免刷新页面后重复播放旧语音。还加入了蓝牙音频唤醒逻辑，降低首次播放无声或延迟的问题。

### Voice Skill

新增 `templates/skills/voice/SKILL.md`，把音色描述、标签使用、高光台词写法整理为可加载技能。GM prompt 中只保留简短原则，具体写法交给 skill，避免系统 prompt 继续膨胀。

## 三、地图交互升级

地图从纯展示升级为可点击交互界面。玩家点击格子、角色或覆盖物时，前端弹出操作菜单，并把选择转成 XML event 发送给 GM。

### 事件模型

```xml
<event source="map" type="move" x="3" y="5"/>
<event source="map" type="interact" character="老陈"/>
<event source="map" type="action" character="哥布林" action="attack"/>
<event source="map" type="interact" overlay="chest1"/>
<event source="map" type="action" overlay="chest1" action="search"/>
```

这些事件不写入普通聊天记录，而是直接进入 primary agent。GM 根据规则判断移动、互动、攻击、搜索等结果，并通过 `message` 与 `update_scene` 给出反馈。

### Scene Schema 扩展

| 字段 | 位置 | 说明 |
|------|------|------|
| `movePath` | `SceneCharacter` | 角色本轮移动路径，前端据此播放动画 |
| `actions` | `SceneCharacter` | 点击角色时显示的自定义动作 |
| `actions` | `SceneOverlay` | 点击宝箱、门、机关等覆盖物时显示的自定义动作 |
| `avatarText` | `SceneCharacter` | 角色头像文字改为模型显式控制，限制 1-2 字 |

### 前端交互

- `TileMapSvg` 支持格子悬停高亮、角色/覆盖物点击命中与坐标换算
- 新增 `MapActionMenu`，按目标类型显示"移动到这里"、"互动"或自定义动作
- 角色支持沿 `movePath` 平滑移动，并可通过 Replay 重放当前分镜动画
- 修复 SVG 缩放/平移后点击偏移问题，改用 `getScreenCTM()` 计算真实坐标
- 地图覆盖物也可以拥有 actions，宝箱、门、机关等对象不再只是静态图标

## 四、All-Primary 架构调整

本期完成一次重要架构调整：**所有用户可见输出都由 primary agent 统一发出**。NPC 仍然是持久 subagent，继续拥有独立 session、记忆和信息隔离，但它们不再直接调用 `message` 面向用户说话。

新的流程：

```
用户输入 / 地图事件
  → Primary(GM) 判断是否需要 NPC
  → notify(NPC) 获取 NPC 内部回应
  → Primary 决定如何转发：message / voice_speak / update_scene
```

### 改动效果

- 消除 NPC spawn 后自动发言导致的 double-greeting
- GM 统一掌控叙事节奏，不再被 NPC 自主消息打断
- 文本与语音天然同步：同一个 GM 决定何时发消息、何时配音
- `notify` 语义简化：去掉 `expect_reply`，调用后总是同步返回 NPC 回应
- NPC prompt 改为"返回角色会说/做什么"，而不是"自己发消息"

这保留了多 Agent 的核心价值：NPC 的上下文和知识仍然物理隔离；变化的是用户可见层的编排权集中到了 GM。

## 五、Prompt 与 Skill 重整

### Primary Prompt

旧 `builder.txt` 被 `primary.txt` 替代，明确 Dice Agent 同时承担 Builder 与 GM：

- 默认 Build 模式，用户明确开始玩时进入 Play 模式
- 所有用户可见内容必须通过 `message` 工具发送
- NPC 台词必须先 `notify`，再由 GM 代发，不允许凭空编造
- 地图事件必须先用 `system` role 简述玩家动作，再解析移动/互动/动作
- 强化 movePath、actions、格子占用、overlay 互动等规则
- 语音作为 GM 工作，不把 TTS 细节泄漏给 NPC

### Skill 目录调整

- `dice` skill 恢复并中文化，新增 DND 检定规则与 `--dc` / `--ac` 参数
- `map` skill 精简，删除过时 GUIDE 和示例，保留更直接的地图编写规范
- 删除 DND 模板骨架，避免过早把冒险结构固定为复杂目录
- workspace 游戏目录规范调整为 `games/<name>/`，角色音色样本建议放在 `games/<name>/voices/`
- `sync:skills` 移入 `dev:backend`，开发启动时自动同步默认技能到默认 workspace

## 六、聊天渲染增强

前端新增统一 `Markdown` 组件，聊天消息支持：

- Markdown 段落、列表、粗体、代码块
- `highlight.js` 代码高亮
- `remark-gfm`，支持 GFM 表格
- 用户消息也按 Markdown 渲染，并保留换行

消息 UI 同时调整了 avatar 逻辑：模型可在 message/voice 中传入 `avatar_text`，系统验证为 1-2 字；普通 agent 消息可不提供头像字，并使用工具/扳手样式区分。

## 七、模型消息与 Interleaved Thinking

模型层新增自定义 `ModelMessage` / `StoredMessage` schema，替代直接依赖 OpenAI SDK 的 `ChatCompletionMessageParam`。这样项目可以显式支持 MiMo 返回的扩展字段。

关键变化：

- `AssistantMessageSchema` 支持 `reasoning_content`
- `OpenAIModel.chat()` 解析并返回 `reasoningContent`
- Agent loop 将 interleaved thinking 保存进历史
- 修复 runLoop 退出前未检查 eventQueue 的问题，避免中途消息丢失
- 及时响应段落补充了"纯文本输出用户不可见"约束，防止模型把用户应该看到的内容写在不可见 assistant content 中

## 八、工具与稳定性改进

### Read 工具

`read` 工具新增二进制文件保护：

- 常见音频、图片、压缩包、PDF、可执行文件等不会按文本读取
- 普通二进制返回类型和大小
- WAV 文件额外返回时长、采样率、声道、位深
- 新增测试覆盖二进制检测和 WAV 元数据

### Workspace 与 Session

- session 列表按创建时间倒序显示，新 session 更容易找到
- workspace meta 文件改为 `-meta.json` 后缀，避免与 config 混淆
- `sync:skills` 在默认 workspace 不存在时自动跳过，避免开发启动报错
- voice auto-play 只对 WebSocket 新消息触发，历史消息加载完成前不误播

### 开发命令

`bun run dev` 改为通过 `run-p` 同时启动后端和 WebUI：

```bash
bun run dev
```

后端启动前执行 `sync:skills`，保证默认 workspace 的技能与模板同步。

## 十一、总结

本期完成的是一次体验层和架构层的双重推进：前端从"显示场景"升级为"玩家可直接点击地图行动"，聊天从纯文本升级为 Markdown 和语音消息，后端则把 NPC 输出权收束到 primary agent，解决了叙事节奏、语音同步和 double-greeting 的一组连锁问题。

DiceCraft 当前已经具备更完整的桌游运行闭环：Builder 创建游戏文件和地图，GM 管理公开场景和隐藏状态，NPC 保持独立记忆，玩家可以通过聊天与地图点击共同推进游戏。
