# DiceCraft 项目总结报告

> 用途：课程结项 / 项目验收介绍  
> 项目名称：DiceCraft — 基于多 Agent 的桌游创作与游玩平台

## 一、项目概述

DiceCraft 是一个基于 Bun + TypeScript 开发的多 Agent 桌游创作与游玩平台。用户只需要用自然语言描述想玩的桌游或 TRPG 场景，系统中的 Builder / GM Agent 会自动设计规则、创建地图、管理状态、生成 NPC，并在 Web 界面中运行游戏。

项目从最初的 CLI 原型逐步演进为完整 Web 应用，最终形成了"自然语言创作游戏 + 多 Agent 运行游戏 + 可视化地图交互 + 角色语音演出"的闭环。

核心目标不是做一个固定规则的桌游，而是做一个能持续生成和运行新桌游的创作平台：

- 用户提出创意
- Agent 生成规则、地图、角色、状态文件和技能
- WebUI 展示聊天、地图、任务和角色信息
- GM 负责推进剧情和规则判定
- NPC 子 Agent 负责独立角色视角和记忆
- 玩家通过聊天和点击地图共同推进游戏

## 二、系统架构

DiceCraft 采用前后端分离但同仓库开发的架构：

| 层级 | 技术 / 模块 | 作用 |
|------|-------------|------|
| 运行时 | Bun + TypeScript | 后端服务、工具执行、测试与构建 |
| 后端框架 | Hono + Bun WebSocket | REST API、实时消息、场景同步 |
| 前端 | React + Vite + shadcn/ui + Tailwind CSS | Web 游戏界面 |
| AI 接入 | OpenAI 兼容 API（MiMo 模型） | 主模型、NPC 模型、TTS |
| Agent 系统 | AgentLoop + SubagentDispatcher | 主 Agent 循环、NPC 子 Agent 调度 |
| 工具系统 | ToolRegistry | 文件读写、bash、消息、通知、场景更新、语音生成 |
| 状态存储 | JSON / JSONL | workspace、session、chat、scene、compact state |
| 技能系统 | `skills/SKILL.md` | 可复用游戏能力、地图规范、骰子、语音指导 |

前端采用三栏布局：

- 左侧：Workspace / Session 管理
- 中间：游戏场景、地图、角色、任务、玩家卡
- 右侧：聊天、Markdown 消息、语音消息、上下文用量

后端通过 WebSocket 推送聊天消息、GM 状态、NPC 数量和场景更新，保证玩家操作后界面可以实时变化。

## 三、技术亮点

### 1. 多 Agent 协作与信息隔离

项目的核心技术亮点是多 Agent 架构。系统中有一个 Primary Agent，同时承担 Builder 和 GM；每个 NPC 都是独立子 Agent，拥有自己的 session、历史和角色记忆。

这种设计带来了真正的信息隔离：

- NPC 之间互不可见
- NPC 只知道 GM 告诉它的信息
- 玩家可以和某个 NPC 说悄悄话，其他 NPC 不会自动知道
- GM 可以向不同 NPC 透露不同粒度的信息
- 隐藏线索、误导、阵营差异、信息不对称博弈都可以自然实现

后期项目进一步采用 all-primary 架构：NPC 不再直接向用户发消息，而是把内部回应返回给 GM，由 GM 统一决定如何呈现。这解决了 NPC 自动抢话、double-greeting、语音与文本不同步等问题，同时保留了独立记忆和信息隔离。

### 2. Agent 工具调用体系

项目实现了统一 Tool 接口和 ToolRegistry，让 Agent 可以通过工具完成真实操作：

- `read/write/edit/glob/grep`：读写和修改工作区文件
- `bash`：在沙箱内运行脚本
- `message`：向用户发送可见消息
- `notify`：咨询 NPC 子 Agent
- `update_scene`：更新可视化场景
- `voice_design` / `voice_speak`：设计和生成角色语音

这使 Agent 不只是聊天模型，而是具备了"创建文件、运行脚本、维护状态、驱动 UI"的行动能力。

### 3. 可持久化的游戏运行系统

DiceCraft 将游戏过程中的关键内容持久化：

- Workspace 配置和游戏资产
- Session 元数据
- 聊天历史 `chat.jsonl`
- Agent 模型历史
- NPC 子 Agent 关联关系
- 场景状态 `scene-state.json`
- 长上下文摘要 `compact-state.json`
- 语音片段文件

因此游戏不是一次性对话。用户可以中断、刷新、恢复，NPC 记忆和游戏状态仍然存在。

### 4. 长上下文自动压缩

项目实现了 Context Compaction，用于解决长时间游戏中的上下文膨胀问题：

- 基于消息体估算 token 用量
- 达到上下文窗口 80% 时自动触发摘要
- 摘要与最近若干轮消息共同组成新上下文
- 摘要状态持久化到 session
- 前端显示上下文用量进度

这让 DiceCraft 更适合长流程 TRPG 或多轮桌游，而不是只能支撑短对话。

### 5. WebSocket 实时应用架构

项目从 CLI 升级为 Web 应用后，后端通过 Hono + Bun WebSocket 提供实时交互：

- 用户消息实时进入 GM
- Agent 消息实时推送到聊天区
- `update_scene` 实时更新地图和角色
- NPC 数量、GM 活跃状态实时显示
- 地图点击事件通过 WebSocket 进入 GM 处理

这使游戏体验从"命令行聊天"变成了"可视化交互应用"。

### 6. 2D 像素风地图渲染与交互

项目实现了完整的 Scene 渲染系统：

- CSV 地图文件描述地图网格
- 10 种地形瓦片：grass、stone、wood、water、wall、lava 等
- SVG 程序化像素风渲染
- 支持缩放、拖拽、悬停高亮
- 支持角色 token、地图标签、覆盖物
- 支持角色阵营颜色
- 支持玩家角色卡、主线任务、状态效果

后续又加入点击交互：

- 点击空格子：移动到这里
- 点击 NPC：互动 / 自定义动作
- 点击敌人：攻击等动作
- 点击宝箱、门、机关：搜索、打开、触发等动作
- 角色 `movePath` 动画和 Replay 重放

地图不再只是展示结果，而是成为玩家输入的一部分。

### 7. 面向 LLM 的数据格式设计

项目中多处格式设计专门考虑了 LLM 生成和编辑的稳定性。例如地图采用 CSV：

```csv
wall,wall,wall,wall
wall,wood,wood,wall
wall,wood,stone,wall
wall,wall,wall,wall
```

相比单字符地图，`wall`、`wood`、`stone` 等单词更自解释，也更方便模型局部编辑和工具替换。SceneState 中数组字段采用全量替换策略，也降低了模型进行复杂增量合并时出错的概率。

### 8. 角色语音生成

项目接入 MiMo TTS，支持角色音色设计和语音克隆：

- GM 可以为重要 NPC 设计音色样本
- 音色样本作为游戏资产保存
- 角色发言时可生成短语音片段
- 前端以语音消息形式播放
- 支持自动播放、进度条、历史消息不误播

语音设计采用"高光台词"策略：不朗读全文，而是提取最有角色感的短句。这更适合游戏演出，也避免语音过长影响节奏。

### 9. Markdown / GFM 消息渲染

聊天系统支持 Markdown、GFM 表格和代码高亮，适合展示：

- 规则说明
- 道具列表
- 战斗结算
- 角色属性表
- 地图或脚本片段
- 构建过程中的计划和检查结果

这提升了 Builder 创建游戏时的信息密度，也让验收演示中的系统输出更清晰。

### 10. 安全边界与工程质量

项目不是简单调用模型，而是建立了较完整的工程边界：

- workspace 路径沙箱，工具只能操作指定目录
- API Key 配置通过 WebUI 管理，不再依赖 `.env`
- masked key 保存时不会覆盖真实 key
- `read` 工具阻止二进制文件按文本读取
- WAV 文件返回元数据而非乱码
- `bun run check` 集成测试、类型检查、lint、prettier
- 测试覆盖 Agent loop、subagent、tool、workspace、session、compaction 等模块

## 四、内容亮点

### 1. 自然语言创建游戏

DiceCraft 的内容生产方式本身就是亮点。用户不需要写代码或配置复杂规则，只要描述想法，Builder Agent 就能：

- 设计游戏背景和目标
- 创建角色和 NPC
- 编写规则与状态文件
- 生成地图
- 设置任务、敌人、物品和互动动作
- 在前端实时预览

这让桌游创作从"手工编写规则"变成了"对话式共同创作"。

### 2. 游戏过程反向沉淀 Skill

项目验证了一个正向循环：游戏过程中产生的好工具可以沉淀为 Skill，之后成为新游戏的默认能力。

早期示例包括：

- `dice`：通用骰子和 DND 检定
- `bluff-number-guess`：虚张声势猜数字
- `map`：地图创建与显示规范
- `voice`：角色音色与高光台词写法

这意味着平台不是只能运行一次性游戏，而是能随着使用不断积累能力。

### 3. 信息不对称桌游能力

传统单模型聊天很难自然实现"不同角色知道不同事情"。DiceCraft 通过 NPC 独立 session 实现了真实信息隔离，因此特别适合：

- 推理游戏
- 阵营游戏
- 谈判游戏
- 酒馆秘密任务
- NPC 各自隐瞒线索
- 玩家与某个角色单独交流

报告中的酒馆游戏示例就体现了这一点：不同 NPC 能掌握不同信息，GM 控制信息流向，用户在互动中探索真相。

### 4. 可视化 TRPG / DND 工作流

项目建立了 DND / TRPG 的基本工作流：

- Build 模式：设计场景、地图、角色、规则
- Play 模式：GM 叙事、NPC 对话、骰子判定、场景切换
- 地图显示：房间、墙体、地形、角色位置
- 玩家行动：聊天输入或点击地图
- 规则判定：骰子工具与状态文件辅助

这让 DiceCraft 不只是聊天机器人，而是具备桌游主持人和地图桌面的双重能力。

### 5. 多模态演出体验

最终版本包含文字、地图、动画和语音：

- GM 用文字叙事
- NPC 有独立头像和名称
- 地图展示玩家和角色位置
- 玩家点击地图触发行动
- 角色移动有路径动画
- 重要台词可以语音播放

这些内容亮点适合课程结项演示，因为它们能直观看到系统从"生成内容"到"运行内容"的完整过程。

## 六、验收演示建议

课程展示时建议按以下流程演示：

1. 打开 WebUI，展示 Workspace、Session 和模型配置
2. 输入自然语言需求，例如"创建一个酒馆调查游戏"或"创建一个地牢入口遭遇战"
3. 展示 Builder 创建地图、角色、任务和状态
4. 切换到 Play 模式，让 GM 开始叙事
5. 与 NPC 对话，展示多 Agent 角色回应
6. 点击地图格子移动角色，展示 movePath 动画
7. 点击 NPC / 宝箱 / 敌人触发动作菜单
8. 调用骰子判定或 DND 检定
9. 播放 NPC 高光语音
10. 展示 Markdown 表格、任务面板、玩家角色卡和上下文用量

这条演示路径能覆盖项目最重要的技术亮点和内容亮点。

## 七、创新点总结

DiceCraft 的创新点可以概括为四个方面：

### 1. 从"AI 聊天"到"AI 创作工具"

系统不只是回答用户问题，而是能创建文件、管理状态、生成地图、设计规则和运行游戏。

### 2. 从"单 Agent"到"多角色协作"

NPC 拥有独立上下文和记忆，GM 控制信息流，能够支持信息不对称玩法。

### 3. 从"文本游戏"到"可视化桌面"

WebUI 提供地图、角色、任务、玩家卡、点击动作、动画和语音，使游戏过程更接近真实桌游体验。

### 4. 从"一次性生成"到"可沉淀能力"

Skill 系统让游戏过程中形成的工具和规则可以复用，平台能力会随着使用持续增长。

## 八、总结

DiceCraft 完成了一个从底层 Agent 循环、工具系统、会话持久化，到 WebUI、地图渲染、地图交互、角色语音和长上下文管理的完整 AI 应用。它展示了大模型不仅可以生成文本，还可以作为游戏设计者、主持人和多角色模拟系统，持续创建和运行复杂互动内容。

从课程项目角度看，DiceCraft 同时具备工程完整度和展示效果：后端有清晰的 Agent / Tool / Session / Workspace 架构，前端有可直接演示的地图和聊天界面，内容侧有桌游、TRPG、NPC 对话、语音演出和信息不对称玩法。这使它适合作为一个完整的 AI 应用开发结项项目进行验收。
