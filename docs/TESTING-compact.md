# Context Compaction 手动测试指南

## 准备工作

### 1. 配置低阈值

为了在短对话中就能触发压缩，需要将 Context Window Tokens 设为较小的值。

1. 启动后端：`bun run dev`
2. 启动前端：`cd packages/dice-craft-webui && bun run dev`
3. 打开 http://localhost:5173
4. 进入 Workspace Settings（设置按钮）
5. 将 **Context Window Tokens** 设为 `50000`（50k）
6. 保存

这意味着压缩阈值 = 50000 × 0.8 = 40000 tokens。大约相当于 160KB 的对话内容（bytes/4）。

### 2. 创建新 Session

在左侧面板点击 "New conversation" 开始一个新对话。

## 测试用例

### 测试 A：正常对话不触发压缩

**步骤**：
1. 发送一条简短消息："你好"
2. 等待回复

**预期**：
- 底部状态栏显示 Context Usage 进度条
- 百分比应该很低（<10%）
- 没有 "COMPACT" 标签
- 进度条为灰色

### 测试 B：长对话触发压缩

**步骤**：
1. 发送多条较长的消息来填充上下文：
   ```
   请你扮演一个奇幻世界的DM，详细描述一个有丰富背景的城镇，包括至少5个NPC，每个NPC有详细的背景故事、性格特点和目标。这个城镇叫做"雾岭镇"，位于一座巨大的山脉脚下。
   ```
2. 等待 AI 回复（会是一段很长的描述）
3. 继续发送后续消息：
   ```
   我想探索城镇的市场区域，告诉我那里有什么有趣的摊位和商人，每个商人卖什么东西，价格是多少。详细描述市场的氛围和人群。
   ```
4. 继续对话几轮，每次都要求详细描述
5. 观察 Context Usage 百分比增长

**预期**：
- 百分比逐渐上升
- 到 70%+ 时进度条变为琥珀色
- 到 90%+ 时变为红色
- 触发压缩后：
  - 显示 "COMPACT" 蓝色标签
  - 进度条颜色变为天蓝色
  - 百分比回落
- 对话内容应该保持连贯（AI 仍然记得之前的关键信息）

### 测试 C：压缩后对话连贯性

**步骤**：
1. 在测试 B 触发压缩后
2. 询问之前对话中的具体细节：
   ```
   刚才你提到的那个铁匠叫什么名字？他有什么特别的技能？
   ```

**预期**：
- AI 应该能回忆起之前提到的 NPC 信息（来自压缩摘要）
- 回答应该与之前的描述一致

### 测试 D：Tooltip 信息验证

**步骤**：
1. 将鼠标悬停在 Context Usage 进度条上

**预期**：
- 显示 tooltip，包含：
  - 当前 token 数 / 阈值 token 数
  - 如果已压缩：显示被压缩的消息条数

### 测试 E：Session 恢复后状态

**步骤**：
1. 进行一段较长的对话
2. 刷新页面（F5）
3. 重新进入同一个 session
4. 发送一条新消息

**预期**：
- Context Usage 指示器在收到第一个回复后恢复显示
- 之前的对话历史仍然存在

### 测试 F：Settings 持久化

**步骤**：
1. 在 Workspace Settings 中设置 Context Window Tokens 为 100000
2. 保存
3. 关闭设置对话框
4. 重新打开设置

**预期**：
- Context Window Tokens 字段显示 100000
- 下方提示 "Compaction starts at 80% of this value."

## 快速触发压缩的技巧

由于 50k 阈值约等于 ~160KB 对话内容，你可以通过以下方式快速触发：

1. 要求 AI 生成长篇内容（详细描述、长故事、多角色）
2. 连续多轮追问细节
3. 使用 tool call 密集的场景（每个 tool 结果都会增加上下文）

通常 3-5 轮详细的 RPG 对话就能触发压缩。

## 故障排查

- **进度条一直为 0%**：检查 Workspace Settings 中 Context Window Tokens 是否设置了非零值
- **压缩不触发**：确认 API 正确返回了 usage 信息（部分 API 代理可能不转发 usage 字段）
- **压缩后 AI 失忆**：检查后端日志是否有摘要生成错误
